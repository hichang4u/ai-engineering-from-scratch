# 문서 및 도표 이해

> 문서는 사진이 아닙니다. PDF, 과학 논문, 청구서, 또는 손으로 작성된 양식은 단순한 이미지 이해로 파악할 수 없는 레이아웃, 테이블, 다이어그램, 파트 노트, 헤더 및 의미 구조를 가지고 있습니다. VLM 이전 스택은 파이프라인: 테세라크 OCR + 레이아웃LMv3 + 테이블 추출 유리스틱스. VLM 파도는 OCR 무료 모델  도넛 (2022), 노그트 (2023), DocLLM (2023) 로 대체하여 구조화된 마크업을 직접 발사합니다. 2026년까지, 국경은 "글로드 오퍼스 4.7에 페이지 이미지를 2576px 네이티브로 먹여주십시오". 이 수업은 문서 인공지능의 3 시대 아크를 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, layout-aware document parser skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 5 (NLP)
**Time:** ~180 minutes

## 학습 목표

- 문서 AI의 세 시대를 설명하십시오: OCR 파이프라인, OCR 무료, VLM 네이티브.
- LayoutLMv3의 세 가지 입력 스트림을 설명하십시오. 텍스트, 레이아웃 (bbox), 이미지 패치, 통합 마스킹.
- 도넛 (OCR 무료, 이미지 → 마크업), 노그트 (과학 논문 → 라텍스), 도클림 (설계 인식 생성), 팔리게마 2 (VLM- 네이티브) 를 비교하십시오.
- 새로운 작업에 필요한 문서 모델을 선택하세요 ( Faktura, 과학 논문, 손으로 작성된 양식, 중국 인수).

## 문제

"이 PDF를 이해하라"는 속임수적으로 어렵죠.

- 텍스트 내용 (신호의 90%).
- 레이아웃 (머리, 파운드 노트, 사이드 바, 두 열 형식)
- 표 (줄, 열, 합성 셀)
- 그림과 다이어그램
- 손으로 쓴 해석은
- 글꼴과 타이포그래피 (저장과 몸매)

원료 OCR는 텍스트를 던지고 나머지는 잃습니다. 청구서에 신경을 쓰는 시스템은 "총액: 1,245 달러"가 아래 오른쪽에서 왔다는 것을 알아야 합니다.

## 개념

### 1기  OCR 파이프라인 (2021년 이전)

클래식 스택:

1. PDF → 페이지마다 이미지
2. 테세랙트 (또는 상업적 OCR) 는 단어별 한계 상자를 가진 텍스트를 추출합니다.
3. 레이아웃 분석기는 블록을 식별합니다 (머리, 테이블, 문장).
4. 테이블 구조 인식기 테이블을 분석합니다.
5. 도메인 규칙 + regex 추출 필드

깨끗한 인쇄 텍스트를 위해 작동합니다. 필기, 왜곡된 스캔, 복잡한 테이블, 비영리 스크립트. 모든 실패 모드는 사용자 지정 예외 경로를 필요로합니다.

### TROCR (2021)

트로커 (Li et al., arXiv:2109.10282) 는 테세라크트의 고전적인 CNN-CTC를 합성 + 실제 텍스트 이미지에 훈련된 트랜스포머 엔코더-디코더로 대체했다. 손문화 및 다국어 텍스트에 대한 청정 승리가 계속되었습니다. 여전히 파이프라인 (탐지자 다음 트로커 다음 레이아웃), 그러나 OCR 단계가 크게 향상되었습니다.

### 2기  OCR 없는 시대 (2022-2023)

첫 번째 OCR 무료 모델은: 검출을 완전히 건너뛰고, 구조화된 출력으로 이미지 픽셀을 직접 지도합니다.

도넛 (Kim et al., arXiv:2111.15664):
- 코더-디코더 트랜스퍼머, 코더는 스윈-B입니다.
- 출력은 형태 이해, 요약 또는 작업에 대한 특정 스키마를 위한 JSON입니다.
- OCR도 없고, 레이아웃도 없고, 검출도 없습니다.

노가트 (Blecher et al., arXiv:2308.13418):
- 과학 논문에 대해 특별히 훈련받았습니다.
- 출력: 라텍스/ 마크다운
- 방정식, 다방정 기둥, 숫자
- 모든 아크시브 파서들이 부르는 모델

이 사람들은 일반주의자가 아니라 전문가입니다. 과학 논문에서 도넛이 실패하고, 청구서에 노가트도 실패합니다.

### 레이아웃LMv3 (2022)

다른 트랙. 레이아웃LMv3 (Huang et al., arXiv:2204.08387) 는 OCR를 유지하지만 레이아웃 이해를 추가합니다.

- 3개의 입력 스트림: OCR 텍스트 토큰, 1 토큰당 2D 경계 상자, 이미지 패치.
- 마스크된 교육 목표는 세 가지 방법 (마스크된 텍스트, 마스크된 패치, 마스크된 레이아웃) 에서 모두 이루어집니다.
- 하류: 분류, 엔티티 추출, 테이블 QA

LayoutLMv3는 OCR 기반 문서 이해의 최고 수준입니다. 양식 및 청구서에 강하다. OCR를 전류로 요구합니다. 표준화된 문서 벤치마크에서 VLM 이전 정확도가 가장 좋습니다.

### 문서 (2023)

DocLLM (Wang et al., arXiv:2401.00908) 는 LayoutLM의 생성형이다. 레이아웃 토큰에 따라 조건화된 자유형 답변을 생성한다. 문서에 대한 QA에 더 좋습니다. 여전히 OCR 입력에 달려 있습니다.

### 에라 3  VLM-이족 (2024+)

2024 VLM는 파이프라인을 완전히 대체할 만큼 좋은 것으로 변했습니다. 전체 페이지 이미지를 고해상도로 VLM에 공급하고, 질문을 해보고 답을 얻습니다.

- LLaVA- NEXT 336- 타일 AnyRes는 작은 문서에 적합합니다.
- Qwen2.5VL 역동적 해상도는 2048+ 픽셀을 원산적으로 처리합니다.
- 클로드 오퍼스 4.7는 2576px 문서를 지원합니다.
- 파리게마 2 (2025년 4월) 는 문서 + 필기에 대한 훈련입니다.

VLM-이생산과 OCR- 파이프라인의 간격은 빠르게 닫혔다. 2026년까지 VLM-이생산은:

- 장면 텍스트 (손으로 작성된 + 인쇄된, 혼합된 스크립트)
- 합성된 세포를 가진 복잡한 테이블
- 텍스트에 삽입된 수학 방정식
- 텍스트 해석이 있는 그림

OCR 파이프 라인은 여전히 이기고 있습니다.

- 순수한 스캔 작업량은 대규모로 페이지 당 지연이 중요하게 됩니다.
- 파이프라인 신뢰성 (분명성 오류와 VLM 환각)
- 감사 가능한 OCR 출력이 필요한 규제된 환경

### 클로드 4.7 / GPT-5 국경

2576 피클스 네이티브 입력으로, 국경 VLM는 인간과 거의 같은 정확도로 이해를 기록합니다. 2026년 초 기준 번호는:

- DocVQA: 클로드 4.7 ~ 95.1, 파리게마 2 ~ 88.4, 노가트 ~ 77.3, 파이프라인 레이아웃LMv3 ~ 83.
- 차트QA: 클로드 4.7 ~ 92.2, GPT-4V ~ 78.
- 시각MRC: 클로드 4.7 ~ 94.

폐쇄형 모델의 격차는 대부분 해상도와 기본 LLM 규모입니다. 7B의 개방형 모델은 몇 점 뒤이지만 따라잡고 있습니다.

### 수학 방정식 및 LaTeX 출력

과학적 논문들은 방정식에 대해 정확한 LaTeX 출력이 필요합니다. Nougat은 이에 대한 훈련을 받았습니다. LaTeX 목표 (Qwen2.5-VL-Math, Nougat 파생물) 로 훈련된 VLM는 사용 가능한 LaTeX를 생성합니다. 명시적인 LaTeX 훈련이 없으면 VLM는 읽을 수 있지만 정확하지 않은 전개를 생성합니다.

2026년 과학 논문 파이프라인: PDF에 누가트를 연쇄하고, 복잡한 페이지에 VLM를 연쇄합니다.

### 손문

여전히 가장 어려운 과제입니다. 혼합 인쇄 + 손으로 작성된 (의사 노트, 작성된 양식) 은 OCR 파이프라인이 여전히 비용에 대해 VLM를 이길 수 있는 곳입니다. 손으로 작성된 VLM는 개선되고 있습니다 (Claude 4.7, PaliGemma 2).

### 2026 요리법

새로운 문서 인공지능 프로젝트:

- 순전히 인쇄된 규모의 청구서: LayoutLMv3 + 규칙, 비용 효율성.
- 혼합 문서 (과학 + 손으로 작성된 + 양식): VLM-이족 (PaliGemma 2 또는 Qwen2.5-VL).
- 아크시브를 완전히 섭취하고 수학을 위한 노가트, 수치를 위한 VLM
- 규제: OCR 파이프라인 + VLM 검증기

## 주요 용어

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OCR pipeline | "Tesseract-style" | Stage-wise stack: detect -> OCR -> layout -> rules; deterministic, fragile |
| OCR-free | "Donut-style" | Image-to-output transformer that skips explicit OCR; single model |
| Layout-aware | "LayoutLM" | Input includes per-token bbox coordinates; unified masking across modalities |
| VLM-native | "Frontier VLM" | Feed page image directly to Claude/GPT/Qwen VLM at high resolution; no pipeline |
| DocVQA | "Doc benchmark" | Document VQA standard; most-cited score |
| Markup output | "LaTeX / MD" | Structured output format instead of free-form text; enables downstream automation |
