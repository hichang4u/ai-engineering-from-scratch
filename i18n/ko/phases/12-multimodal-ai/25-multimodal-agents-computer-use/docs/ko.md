# 멀티모달 에이전트 및 컴퓨터 사용 (캡스톤)

> 2026 프론터리 제품은 스크린샷을 읽고 버튼을 클릭하고 웹 UI를 탐색하고 양식을 채우고 워크플로우를 끝에서 끝으로 완료하는 멀티모달 에이전트입니다. SeeClick과 CogAgent (2024) 은 GUI 지형 원시성을 증명했다. 페렛 UI가 모바일로 추가되었습니다. 차트 에이전트는 차트들을 위한 시각적 도구 사용법을 도입했습니다. 비주얼웹아레나와 에이전트비스타 (2026) 는 국경 추격의 기준이며, 심지어  지미니 3 프로와 클로드 오푸스 4.7 점수는 에이전트비스타의 어려운 작업에 ~30% 정도다. 이 톱스톤은 12 단계의 모든 스레드를 하나로 묶어줍니다. 인식 (고상화 VLM), 추론 (툴 사용과 함께 LLM), 지형 (조ordinate output), 장평선 메모리 및 평가.

**Type:** Capstone
**Languages:** Python (stdlib, action schema + agent loop skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 09 (Qwen-VL JSON), Phase 14 (Agent Engineering)
**Time:** ~240 minutes

## 문제

예약 사이트 작업 흐름: "4월 15일 도쿄로 가는 비행기를 찾아보세요. 800달러 이하의 통로 좌석을 예약하세요".

멀티모달 에이전트는

1. 브라우저의 스크린샷을 찍어보세요.
2. 스크린샷 + URL + 목표를 계획으로 분석합니다.
3. 구조화된 동작을 수행: 클릭 (x,y), "토키오" (element E) 를 입력, 아래로 스크롤, 선택 (라디오 버튼)
4. 이 동작을 브라우저에 적용하세요.
5. 새로운 상태를 관찰하세요 (다음 화면 촬영).
6. 작업이 완료될 때까지 반복하십시오.

각 단계는 멀티모달 VLM 호출입니다. VLM 출력은 JSON를 분석할 수 있어야 합니다. 단계마다 오류가 합쳐져 있으므로 복구가 중요합니다.

## 개념

### GUI 지형  원시

GUI 지형화는: 스크린샷과 자연어 명령어를 제공하면 클릭 (또는 다른 동작) 을 위해 (x, y) 좌표를 출력합니다.

SeeClick (arXiv:2401.10935) 는 규모의 첫 번째 오픈 결과였습니다. 합성 + 실제 GUI 데이터에 VLM를 미세하게 조정하고, 푸른 텍스트 토큰으로 출력 좌표를 작동합니다.

코그 에이전트 (arXiv:2312.08914) 는 밀집된 UI에 1120x1120 고해상도 코딩을 추가했습니다. 점수는 웹 내비게이션에서 ~84%입니다.

페렛 UI (arXiv:2404.05719) 는 모바일 UI에 초점을 맞추고 iOS 접근성 데이터와 통합됩니다.

출력 형식은 일반적으로 JSON입니다.

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc`복구에 도움이 됩니다. 화면 촬영 사이에 좌표가 이동하면, 의미적 단서가 시스템을 다시 지탱할 수 있습니다.

### 행동 계획

일반적인 행동 스키마는 6-10 가지 행동 유형을 가지고 있습니다.

- `click`(x, y)
- `type`: ( 텍스트, x?, y?)
- `scroll`: (방향, 금액)
- `drag`(x0, y0, x1, y1)
- `select`: (option_index)
- `hover`(x, y)
- `navigate`(url)
- `wait`(ms)
- `done`: (성공, 설명)

에이전트는 한 단계에 한 동작을 내보내고 브라우저 팩은 새로운 상태를 실행하고 반환합니다.

### 스크린샷만 대 접근성 트리

두 개의 입력 모드:

- 스크린샷만: 전체 이미지, 구조 정보 없습니다. 가장 일반; 모든 앱에서 작동합니다.
- 접근성 트리: 구조화된 DOM / iOS 접근성 정보. 지형에 훨씬 더 신뢰할 수 있습니다. 나무가 사용할 수 있는 곳에서 작동합니다.
- 하이브리드: 모두, 나무가 원자력 동작을 위한 신뢰할 수 있는 토지로서와 의미적 맥락을 위한 스크린샷으로.

생산 에이전트는 가능한 경우 하이브리드를 사용합니다. 브라우저 자동화 (셀레늄 + 접근성) 는 항상 나무를 가지고 있습니다. 데스크톱 앱은 때때로합니다.

### 장평선 기억

20단계 작업 흐름은 20개의 스크린샷을 생성합니다. VLM의 컨텍스트는 빠르게 채워집니다. 세 가지 압축 전략:

- 서술 체인: 5단계마다 일어난 일을 서술하고 오래된 스크린샷을 내려놓습니다.
- 스kip 프레임: 첫 번째, 마지막, 그리고 3번째 스크린샷을 유지하세요.
- 도구로 녹음된 로그: 실행 작업을 수행하고, 수행된 내용을 텍스트 로그로 보관하고, 오래된 스크린샷을 다시 보지 마십시오.

클로드의 컴퓨터 사용 API는 로그 패턴을 사용합니다. 더 간단하고 더 신뢰할 수 있습니다.

### 시각 도구 사용

차트 에이전트 (arXiv:2510.04514) 는 차트 이해를 위한 시각 도구 사용: crop, zoom, OCR, call external detection. 에이전트는 "crop to region (100, 200, 300, 400) "를 출력할 수 있으며, OCR를 도구 호출으로 호출할 수 있습니다. 도구는 텍스트를 반환합니다. VLM는 추론을 계속합니다.

이 패턴은 일반화합니다. 셋 오브 마크 팅, 지역 해설, 그리고 외부 탐지 도구 모두 같은 "툴 호출 출력, 구조화된 응답을 수신" 스케마에 적합합니다.

### 2026년 기준

- 스크린스팟 프로. GUI 지형화 1k 웹 스크린샷. SOTA Qwen2.5-VL-72B ~ 85% 오픈. 프론티어 ~ 90%
- VisualWebArena. 엔드-투-엔드 웹 작업 (샵, 포럼, 광고) SOTA ~ 20% 오픈.
- AgentVista (arXiv:2602.23166). 2026년 가장 어려운 기준. 12개의 도메인에서 현실적인 작업 흐름. 프론티어 모델은 27-40%; 오픈 모델은 10-20%
- 웹 아레나 / 웹샵. 오래된 기준; 국경에 의해 포화

### 왜 아직도 힘들어

요원 성능의 병목:

1. 시각 지형은 미세한 규모로 "X를 클릭하세요"는 모바일 해상도에 실패합니다.
2. 10개의 행동 후, 에이전트는 목표로부터 멀어진다.
3. 오류 복구: 클릭 실패 (실동 버튼) 에, 탐지 + 복구는 거의 훈련된 데이터입니다.
4. 페이지 간 컨텍스트. 탭이나 긴 양식을 는 상태가 사라집니다.

연구 방향: 메모리 아키텍처, 명시적인 재계획, 멀티모달 검증 (사진 성공에 대한 화면 촬영 일치).

### 돌이 만들어서

최종 임무: 컴퓨터 사용 에이전트를 구축하여

1. 예약 사이트 모크 페이지의 HTML+ 스크린샷을 읽습니다.
2. 여러 단계 순서를 계획합니다: 검색 → 선택 → 작성 폼 → 제출.
3. 액션 스케마에 맞는 JSON 액션을 발송합니다.
4. 고정된 10개의 작업으로 평가합니다.

## 주요 용어

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| GUI grounding | "Click coordinates" | Model outputs (x,y) for the target of an instruction on a screenshot |
| Action schema | "Tool definitions" | JSON description of valid actions (click, type, scroll, drag) |
| Accessibility tree | "Structured DOM" | Machine-readable UI hierarchy from browser/iOS APIs |
| Hybrid agent | "Screenshot + tree" | Uses both image and structured info; more reliable than either alone |
| Visual tool use | "Zoom/crop/detect" | Agent calls external vision tools (OCR, detection) mid-plan |
| Summary-chain | "Memory compression" | Periodic text summaries replace long screenshot history |
| VisualWebArena | "E2E web bench" | 2024 benchmark for end-to-end web tasks |
| AgentVista | "2026 hard bench" | 12-domain realistic workflows; even Gemini 3 Pro scores ~30% |
