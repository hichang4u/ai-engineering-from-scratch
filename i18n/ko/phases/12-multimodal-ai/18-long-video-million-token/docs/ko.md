# 수백만 명 의 언어 의 맥락 에서 긴 비디오 를 이해 하는 것

> 1시간짜리 4K 비디오는 24FPS로 패치하고 임베디드되어 60백만 개의 토큰을 생산합니다. 2시간짜리 포드캐스트 에피소드가 30만 토큰을 기록했습니다. 전체 블루레이 장편영화, 심지어 공격적인 펀딩으로 압축되더라도, 수백만 개의 토큰입니다. 구글의 Gemini 1.5 (2024년 3월) 는 1시간 동안의 동영상을 통해 10백만 개의 토큰 컨텍스트로 신뢰성 있는 바늘-이-하이 스택 회수 작업을 수행하여 이 시대를 개시했습니다. LWM (Liu et al., 2024년 2월) 은 반지 주의의 확장 경로를 보여주었다. 롱비라와 비디오- XL은 섭취량을 더 확장시켰다. 비디오 에이전트는 원본을 에이전틱 검색으로 교환했습니다. 각 접근법은 컴퓨팅, 회수 및 엔지니어링 복잡성에 대한 다른 타협입니다. 이 교훈은 그들을 옆으로 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, needle-in-haystack simulator + agentic-retrieval router)
**Prerequisites:** Phase 12 · 17 (video temporal tokens)
**Time:** ~180 minutes

## 학습 목표

- 다양한 FPS와 융합에서 장형 비디오에 대한 전체 시각 토큰 수를 계산하십시오.
- 세 가지 확장 경로를 설명하십시오: 무형 컨텍스트 (Gemini 1.5), 링 관심 (LWM), 토큰 압축 (LongVILA / Video-XL).
- 정확성과 지연성에서 원시 컨텍스트 비디오 VLMs와 에이전틱 검색 비디오 VLM (VideoAgent) 를 비교하십시오.
- 30분짜리 동영상 촬영을 위해 바늘에 꽂힌 짚무늬 테스트를 설계하고 특정 순간에 회수량을 측정합니다.

## 문제

Qwen2.5VL 크기의 패치의 단일 프레임은 네이티브 해상도 384개로 약 729개의 토큰입니다. 3x3 뷰팅에서는 한 프레임에 81개의 토큰입니다. 1 FPS = 1800 프레임 = 145,800개의 토큰의 30분 클립. 2025년까지 가능한 오픈 VLM, 꽉 찼습니다. 2 FPS에서 291,600개의 토큰은 가장 큰 맥락에만 적합합니다.

1 FPS에서 2시간짜리 영화는 583k 토큰입니다. 대부분의 2026 오픈 모델은 물론, Gemini 2.5 Pro 또는 더 공격적인 펀딩이 필요합니다.

세 개의 스켈링 경로가 등장했습니다.

## 개념

### 경로 1: 무작위 맥락 (Gemini 1.5, Claude Opus)

문제를 해결하기 위해 하드웨어를 던져서, 수백만 개의 토큰으로 컨텍스트를 확장하고, 모든 것을 한 번으로 처리합니다.

제미니 1.5 프로는 1M 토큰과 함께 출시되었습니다. 제미니 1.5 울트라에서 10M, 제미니 2.5 프로는 2026년에 신뢰할 수 있는 시간 동안 비디오를 제공합니다. 논문 (arXiv:2403.05530) 은 99.7%까지 ~ 9.5M 토큰으로 바늘에 잔디줄기 회수 기록을 기록합니다.

엔지니어링: 메모리 계층 (지역 + 글로벌 + 희소) 과 함께 사용자 지정 주의 구현 및 장 контекст 효율을 위한 MoE 전문가 라우팅.

### 경로 2: 반지 주의 (LWM, LongVILA)

반지 주의는 각 장치가 한 조각을 보유하는 "반지"의 장치들 사이에서 긴 순서를 배포합니다. 전체 순서에서의 주의는 각 장치가 반지 패턴으로 그 조각을 다음으로 보내어 부분적인 관심을 계산하고 합쳐서 발생합니다.

LWM (Liu et al., 2024) 는 1M 토큰 컨텍스트 모델을 이렇게 훈련시켰다. 훈련은 컨텍스트와 선형적으로 계산하는 척도를 계산합니다. 사각형이 아닌 사각형이 아닙니다.

LongVILA (arXiv:2408.10188) 는 VLM에 패턴을 조정했다. 프레임 당 192 토큰 = 268k 컨텍스트에 1400-프레임 비디오, 8방향 평행성을 통해 반지 주의를 훈련했다.

### 3번 경로: 토큰 압축 (Video-XL, LongVA)

무작위 맥락보다 저렴합니다. LLM가 순서를 보기 전에 공격적으로 압축합니다.

비디오-XL (arXiv:2409.14485) 는 시각적 요약 토큰을 사용합니다: N 프레임의 각 클립은 N 위에 참석하는 단일 " 요약" 토큰을 생성합니다. 추론에서 LLM는 클립에 한 요약 토큰을보고 맥락을 크게 축소합니다.

롱비아는 "장기 컨텍스트 전송" 기술을 통해 LLM 컨텍스트를 200k에서 2M로 확장합니다.

토큰 압축은 확장성을 위해 특정 시간표에서 회수되는 것을 거래합니다. 모델은 일반적으로 무슨 일이 일어났는지 알고 있지만 때로는 정확한 프레임을 놓치고 있습니다.

### 4번 경로: 에이전트 검색 (VideoAgent)

LLM에 전체 비디오를 제공하지 말고, 비디오를 데이터베이스로 취급하고 LLM를 사용하여 문의하십시오.

비디오 에이전트 (arXiv:2403.10517):

1. LLM는 질문을 읽습니다.
2. LLM는 관련 클립을 검색하는 도구를 요청합니다 ("고양이 있는 세그먼트를 보여줘").
3. 도구는 클립 시간표와 일치하는 것을 반환합니다.
4. LLM는 VLM를 통해 그 클립을 읽습니다.
5. LLM는 답을 작성하거나 후속 질문을 합니다.

이것은 긴 비디오에 적용되는 LLM-as-agent 패턴입니다. 저렴한 추론 (관련된 클립만 암호화), 더 어려운 엔지니어링 (출원 품질은 병목이됩니다).

### 밭에 나늘을 넣는 기준

표준 장막 테스트: 비디오의 무작위 지점에 독특한 시각적 또는 텍스트 표시기를 삽입하고, 그것을 상기시켜야 하는 질서를 요청합니다.

메트릭: 비디오 길이를 통해 Recall@k 및 마커 위치.

제미니 2.5 프로는 최대 90 분짜리 비디오에서 99% 회수점을 얻습니다. 오픈 72B 모델 (Qwen2.5-VL-72B, InternVL3-78B) 는 30 분 동안 ~85-90% 점수를 얻으며 60을 넘습니다.

비디오 에이전트는 2시간 이상으로 원자 맥락 모델을 일치하거나 이길 수 있습니다. 도구가 좋으면 검색이 바늘에 닿기 때문입니다.

### 어떤 길을 선택해야 할까요?

경계 정확성 15분 클립: 오픈 72B + 네이티브 컨텍스트는 일반적으로 작동합니다. Qwen2.5-VL-72B를 선택하십시오.

30분~1시간 동안의 콘텐츠: 롱비라 또는 비디오-XL 오픈, 겐비 2.5 프로 종료. 품질 바는 중요합니다.

2시간 이상 콘텐츠: 비디오 에이전트 또는 유사한 검색 패턴.

### 2026 생산 패턴

실제적으로, 생산 장 비디오 파이프라인은 하이브리드입니다:

1. 전체 비디오에서 동적 FPS 샘플링 + 공격적인 펀딩을 실행하십시오 (100k 토큰 글로벌 표현을 얻으십시오).
2. 72B VLM에 통보를 보내서 글로벌 요약을 받으세요
3. 사용자가 상세한 질문을 한다면, 요약을 인덱스로 사용하여 에이전시 검색을 실행하십시오.

이것은 글로벌 이해를 위한 무작위 맥락과 지역 세부사항을 검색하는 것을 결합합니다.

## 사용 하 고

`code/main.py`이 부분의 본문은

- 1분에서 3시간까지의 비디오 토큰 예산을 FPS + 분량에서 계산합니다.
- 줄에 바늘을 넣는 시뮬레이션을 합니다. 무작위 시간표에 표시기를 주입하고 질문을 하고, 회수점을 기록합니다.
- 하류 VLM에 공급하기 위해 특정 클립을 선택하는 에이전틱 검색 라우터 시뮬레이터를 포함합니다.

예산 테이블을 실행하고 규모의 격차를 감지하십시오.

## 주요 용어

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Brute context | "Just more tokens" | Scale LLM context to millions of tokens; process everything in one pass |
| Ring attention | "LWM-style parallel" | Distributed attention pattern where each device holds a chunk and rotates |
| Token compression | "Summary tokens" | Reduce per-clip tokens via a learned compressor before the LLM |
| Needle-in-haystack | "NIH test" | Insert a unique marker at a random point, ask model to recall it at test time |
| Agentic retrieval | "LLM as query planner" | LLM asks a retrieval tool for relevant clips, reads them via a VLM, composes answer |
| VideoAgent | "Retrieval pattern for video" | Canonical agentic-retrieval design: question -> tool -> clip -> answer |
