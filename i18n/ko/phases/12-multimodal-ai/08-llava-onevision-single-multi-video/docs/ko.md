# LLaVA-OneVision: 단일 이미지, 다중 이미지, 비디오

> LLaVA-OneVision (Li et al., 2024년 8월) 이전에는 오픈 VLM 세계는 별도의 혈통을 가지고 있었다: 단일 이미지들을 위한 LLaVA-1.5, Mantis 및 VILA와 같은 멀티 이미지 모델, Video-LLaVA 및 Video-LLaMA와 같은 비디오 모델. 각각 자신의 기준을 얻었고 다른 사람들에게 실패했습니다. LLaVA-OneVision는 하나의 교육과정이 하나의 모델을 세 가지 시나리오에 지배할 수 있도록 훈련시킬 수 있다고 주장했으며, 새로운 작업 전송 효과 (영화로 수출되는 단일 이미지 기술, 단일 이미지로 수출되는 멀티 이미지 추론) 는 전문가들의 합을 이길 수 있다고 주장했다. 레시피는 매우 간단합니다. 시나리오를 통해 일정하게 유지되는 시각적 토큰 예산과 함께 한 이미지에서 OneVision (다 이미지) 로 비디오로 이동하는 명시적인 교육과정입니다. 이 수업은 예산과 교육과정, 그리고 새로운 행동들을 알려줍니다.

**Type:** Build
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**Time:** ~180 minutes

## 학습 목표

- 단일 이미지, 멀티 이미지 및 비디오 입력에서 일정하게 유지되는 시각적 토큰 예산을 설계하십시오.
- 하나의 이미지에서 비디오로 기술을 전달하는 훈련 교육과정을 주문하세요.
- 왜 하나의 모델이 올바른 교육과정을 수행할 때 동일한 매개 변수 수를 가진 전문가들을 능가하는지를 설명해 주십시오.
- LLaVA-OneVision에서 보고된 세 가지 신흥 기능을 명명하세요: 멀티 카메라 추론, 세트 오브 마크 팅, 아이폰 스크린샷 에이전트.

## 문제

이미지, 멀티 이미지, 비디오 모두 모델에 대해 다르게 강조합니다.

단일 이미지는 OCR와 세밀한 세부 사항을 포착하기 위해 고해상도 토큰 (AnyRes, ~ 2880 시각 토큰) 을 필요로 합니다. 샘플 당 예산: 한 이미지, 2880 토큰.

멀티 이미지에는 중간 해상도의 여러 이미지 (~576 토큰 각) 를 요구하므로 이미지 간의 추론은 맥락에 적합합니다. 샘플 당 예산: 4-8 이미지, 576 개, 2300-4600 토큰.

비디오는 시간적 역학을 캡처하기 위해 낮은 해상도의 많은 프레임 (분합 후 프레임당 ~ 196 토큰) 을 필요로 합니다. 샘플 당 예산: 8-32 프레임, 196 개, 1600-6200 토큰.

개별 모델을 훈련한다면 하나의 예산을 선택합니다. 하나의 모델을 훈련한다면 맥락을 훼손하지 않고 상식적으로 시나리오를 확장할 수 있는 예산이 필요합니다.

1Vision 이전, 기본 대답은 "하나의 시나리오를 훈련시키고 다른 시나리오를 무시한다". 비디오-LLaVA는 추가 훈련 단계와 함께 이미지 모델에 비디오를 리트라피트했다. LLaVA-NeXT는 타일링으로 멀티 이미지 지원을 추가했다. 아무도 세 가지를 깨끗하게 처리하지 않았다.

## 개념

### 원비전 토큰 예산

LLaVA-OneVision는 시나리오별로 다르게 할당된 샘플별로 약 3000~4000개의 시나리오 토큰의 통합 시각 토큰 예산을 선택합니다.

- 단일 이미지: AnyRes-9 (3x3 타일 + 니얼), 각 타일 (384개, 729개의 패치), 공격적인 쌍선형 펀딩 (2x2 → 182개 타일) 총: 9 * 182 + 182 = 1820개의 토큰 또는 AnyRes-4 (729개 타일 = 2916 + 729)
- 멀티 이미지: 각 이미지 중소 해상도 (384, 타일링이 없습니다), 729 토큰은 융합이 없습니다. 예산 6 이미지 → 4374 토큰.
- 비디오: 384 해상도 32 프레임, 공격적인 3x3 억 선 풀 → 81 토큰 한 프레임. 총: 32 * 81 = 2592 토큰.

할당은 대략 일정한 총 토큰을 유지합니다. LLM는 결코 맥락을 뚫는 배트를 보지 않습니다. 코더는 각 시나리오에 따라 다른 기하학을 생성하지만 LLM는 동일한 예산을 소비합니다.

### 3단계 교육과정

LLaVA-OneVision 열차는 세 단계로 이루어집니다.

1. 단일 이미지 SFT (단계 SI). 모든 데이터는 단일 이미지 + 텍스트입니다. 고 해상도 AnyRes 입력에 훈련합니다. 이것은 인식, OCR 및 미세한 이해를 가르칩니다. LLaVA-NeXT 데이터와 OneVision 특정 단일 이미지 데이터를 사용합니다.
2. 원비전 SFT (단계 OV). 단일 이미지 + 멀티 이미지 + 비디오를 혼합 (일본적으로 샘플된 프레임). 통일 토큰 예산에 대한 훈련. 이것은 모델에 이질적인 배치 모양을 처리하는 것을 가르칩니다. 무중 리셋 은 단계 SI에서 계속됩니다.
3. 작업 전송 (단계 TT). 목표 작업 혼합을 계속하여, 일반적으로 제품에 따라 멀티 이미지 또는 비디오에 더 무거운 작업을 수행합니다. 배포를 위해 선택적 미세 조정.

중요한 것은 교육과정 순서가 중요합니다. 비디오 먼저 또는 멀티 이미지 먼저 훈련은 동일한 데이터에도 불구하고 단일 이미지 먼저보다 더 나쁜 이미지 성능을 생산합니다. 논문은 이것을 명시적으로 삭제합니다.

### 교육 계획 이 작동 하는 이유

단일 이미지 훈련은 인식 기반을 구축합니다. 패치 토큰은 미세한 시각적 특징을 가지고 있습니다. LLM는 텍스트와 통합하는 것을 배우습니다. 다중 이미지 및 비디오는 강력한 인식 기반이 없으면 배우기 어려운 구조적 도전을 (어떤 이미지, 어떤 일이 먼저 발생했습니다.)

모든 시나리오를 처음부터 함께 훈련하면 모델은 인식 (배치 당 한 개의 이미지 데이터 제한) 과 초부 구조 (많은 멀티 이미지 / 비디오 데이터) 에 적합합니다. 결과는: 크로스 이미지 추론 패턴을 따르는 모델이지만 시각적으로 습니다.

교육과정 순서는, 단계 SI에서 인식력을, 단계 OV에서 구성/시간적 추론을, 둘 다 잃지 않고 제공합니다.

### 새로운 시나리오 간 기술

LLaVA-OneVision 논문은 세 가지 새로운 기능을 보고합니다.

1. 멀티 카메라 추론. 멀티 이미지 + 비디오에 별도로 훈련; 추론에서 멀티 카메라 운전 장면에 대해 추론하도록 요청. 모델은 훈련에서 정확한 형식을 보지 않았지만 올바른 시각을 통합합니다.
2. 표지판 설정: 사용자가 번호판 표지판으로 이미지의 객체를 표지판으로 설명합니다. 모델은 "표지판 3이 7에 비해 무엇을 하는지"에 대해 설명합니다. 표지판이나 표지판에 대한 훈련은 없습니다. 공간 지형 + 다중 이미지 참조의 조합에서 배운다.
3. 아이폰 스크린샷 에이전트. 사용자는 아이폰 화면의 스크린샷을 제공하고 다음 클릭을 계획하도록 요청합니다. UI 스크린샷, 사용자 작업 흐름의 비디오 및 쌍 전/후 멀티 이미지에서 훈련합니다. 에이전트 사용 사례에 일반화합니다.

이것은 훈련된 과제가 아니라 교육과정의 구성 구조에서 나온 과제입니다.

### 시각적 토큰을 합성

토큰 예산은 융합이 필요합니다. OneVision는 2D 패치 그리드에서 2차원 인터폴레이션을 사용합니다. 24x24 = 576 패치가 12x12 = 144 (2x 요소) 또는 8x8 = 64 (3x 요소) 이됩니다. 융합은 로컬리티를 보존하기 위해 토큰 공간이 아닌 패치 그리드 공간에서 수행됩니다.

각 시나리오에 따라 펀딩 요소의 선택은 자체적으로 하이퍼 파라미터입니다. 펀딩 적은 것 = 더 많은 토큰 = 더 풍부한 표현. 더 많은 펀딩 = 더 적은 토큰 = 더 많은 프레임 / 이미지 적합.

### LLaVA-OneVision-1.5

2025년 후속 (LLaVA-OneVision-1.5, arXiv 2509.23661) 은 교육 데이터, 모델 무게 및 코드에서 "완전히 개방"되어 있습니다. 일부 벤치마크에 대한 독자적 격차와 일치하고 레시피를 민주화합니다. 동일한 교육과정, 더 많은 데이터, 더 나은 기반 LLM. 건축 변경은 없습니다.

### Qwen2.5-VL와 비교

Qwen2.5-VL (강좌 12.09) 는 다른 선택을 합니다. 고정된 펀딩 대신 M-RoPE와 동적 FPS를 사용합니다. 입력을 가진 예산 스케일  1 분기의 비디오는 5 초짜리 비디오보다 더 많은 토큰을 사용합니다. LLaVA-OneVision는 예산을 수정하고 펀딩을 확장합니다. 둘 다 작동합니다. 예측 가능성에 대한 구성성을 교환합니다.

## 사용 하 고

`code/main.py`원비전형 VLM의 교육과정 및 예산 계획자입니다. 샘플에 대한 토큰 예산과 목표 시나리오 혼합 (예컨대 40% 단일 이미지, 30% 다 이미지, 30% 비디오) 를 고려하면:

- 각 시나리오에 따라 해상도, 융합 요소 및 프레임을 할당합니다.
- 모든 시나리오가 공유 예산에 맞는지 확인합니다.
- 보고서는 예상된 토큰 수, LLM FLOPs, 그리고 어떤 시나리오가 토큰화되지 않은지 보고합니다.
- 단계별 훈련 스케줄을 인쇄합니다.

이를 통해 OneVision의 정돈을 계획하거나 VLM 배포의 요구에 따른 비용을 건강검진할 수 있습니다.

## 운동

1. 당신의 제품은 80% 단면 이미지, 10% 다면 이미지 (2-4 이미지), 10% 비디오 (8-16 프레임) 를 지원합니다. 토큰 예산을 설계하십시오. 무거운 다면 이미지를 하지 않는 데에 절약되는 추가 예산은 어디에 넣을 것인가?

2. LLaVA-OneVision 섹션 4.3 (출현 능력) 을 읽어 보세요. 교육과정에서 열릴 가능성이 있는 네 번째 출현 능력에 대해 제안하세요. 그러나 논문은 보고하지 않았습니다.

3. 교육과정 순서를 바꿔서  먼저 멀티 이미지, 다음 단일 이미지, 다음 비디오를 열라. 어떤 기준이 떨어지는지, 왜 떨어지는지 예측하라.

4. 이 논문은 샘플당 8개의 프레임에 훈련된 비디오 벤치마크를 보고합니다. 결론적으로 30초짜리 비디오로 일반화되는가? 무엇이 먼저  토큰 예산이나 시간적 추론을 깨고 있습니까?

5. 24x24 패치의 2선형 펀딩이 12x12로 되면 4x의 펀딩이 dim에 줄어들게 됩니다. stdlib 파이썬에서 펀딩을 구현하고 2x2 블록의 평균이 2선형 출력과 일치하는지 확인합니다.

## 주요 용어

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OneVision scenario | "Single-image, multi-image, or video" | One of three input shapes the unified VLM handles; the budget stays constant across |
| Token budget | "How many tokens per sample" | Total visual tokens the LLM sees per training / inference sample, typically 3000-4000 |
| Curriculum | "Training order" | Stage ordering (single-image → multi-image → video) chosen for emergent transfer |
| Bilinear pooling | "Token shrink" | Applying bilinear interpolation to the patch grid (2D) to reduce token count while preserving locality |
| Emergent skill | "Not trained, still works" | Capability that appears at inference without matching training data, due to curriculum composition |
| AnyRes-k | "k-tile setup" | k sub-tiles of fixed resolution plus one thumbnail, typical $k \in \lbrace 4, 9 \rbrace$ |
| Task transfer | "Cross-scenario generalization" | Skills learned on single-image that apply to video (and vice versa) via shared backbone |
