SHARED 키-값 캐시와 동시다발적으로 동일한 LLM의 N 인스턴스를 실행합니다. 모든 노동자는 다른 노동자의 생성된 토큰을 즉시 볼 수 있습니다. 현대적인 추론 모델은 QwQ, DeepSeek-R1 을 통해 어떤 정비 없이 공유된 캐시를 통해 자기 조정할 수 있습니다. 이 접근법은 실험적이지만, 스펙 디코딩과 정렬하게 자리잡고 있는 추론 평행성의 완전히 새로운 축을 열고 있습니다. 이 교훈은 두 명의 노동자 호그윈드를 구현합니다! stdlib 파이썬에서 시뮬레이터와 공유 캐시 협업이 기존 모델의 추론 능력에서 나타나는 이유를 설명합니다.

## 문제

현대 LLM는 긴 사슬의 추론을 생산함으로써 어려운 문제를 해결합니다. 단계적 논리 5000 토큰은 일반적입니다. 수만 개의 토큰은 깊은 수학 문제에 발생합니다. 70B 모델에서 35 토큰/초 디코딩에서 50k 토큰은 24 분입니다. 상호 작용하는 모델은 아닙니다.

추측 디코딩 (단계 10 · 15) 은 하나의 순서 내에서 병렬화함으로써 3-5x 속도를 제공합니다. 이전에는 자율 퇴행 디코딩의 순서적 의존도가 하드 천장입니다. 새로운 토큰은 이전 토큰에 달려 있습니다.

명백한 질문은, 우리는 순서들을 병렬화 할 수 있을까요? 같은 문제에 대한 동일한 모델의 여러 복사본을 실행하고, 협력하고, 작업을 나누도록 합시다.

이전 작업: 투표 집합 (N 모델을 실행, 다수 답변을 선택), 생각의 나무 (분자 논리 경로 및 재 조합), 그리고 다중 에이전트 프레임워크 (모든 에이전트에게 하위 작업을 할당하고 조정자를 사용한다). 이 모든 것은 특정 작업 영역에 도움이 된다. 그들은 모두 명시적인 조정 기계도 도입합니다.

호그와일드! 추론은 다른 접근 방식을 취합니다. N 노동자들은 하나의 KV 캐시를 공유합니다. 모든 노동자는 다른 노동자의 생성된 토큰을 즉시 보며 마치 그 자신의 맥락처럼 볼 수 있습니다. 훈련이나 정비 없이 일하는 노동자들은 일을 어떻게 나누는지 알아내기 위해 노력합니다. 현대적인 추론 모델 (QwQ, DeepSeek-R1, 클로드 가족 추론 모드) 은 공유된 캐시를 읽고 "노동자 2가 이미 기본 케이스를 처리한 것을 보니까, 저는 induktive 단계에 대해 작업할 것입니다".

스피드업은 2026년 4월부터 작업량에 의존하고 실험적인 것이지만, 이 아이디어는 추론 평행성의 새로운 축을 열기 때문에 알 가치가 있습니다.

## 개념

### 설정

N 작업자 프로세스를 초기화하여 모두 같은 LLM를 실행합니다. 작업자당 KV 캐시를 대신, ONE 공유 캐시를 유지하십시오. 작업자가 `i`토큰을 생성합니다`t_j`, 토큰은 다음 위치에서 공유 캐시에 기록됩니다.`k`다음 단계로 이동하면 현재 캐시 상태를 읽습니다 (N 작업자 모두가 지금까지 생성한 모든 것을 포함합니다).

단계 시간에, 작업자들은 토큰을 작성하기 위해 경주한다. 작업자 개개인 위치 지수가 없습니다. 캐시는 단일 성장 순서입니다. 순서는 도착 시간에 의해 결정됩니다.

### 왜 협조가 발생하는가

노동자들은 일방적인 지시를 공유합니다. 일반적으로 "당신은 이 문제에 대해 함께 일하는 N 사례 중 하나입니다. 각각의 사례는 공유된 메모리를 읽고 다른 사례가 무엇을 썼는지 볼 수 있습니다. 과잉 작업을 피하세요". 추론 모델은 캐시를 읽고 문제의 어떤 부분들이 이미 시도되었는지 알아보고 (일반적으로 하지만 항상 그렇지 않습니다) 탐구되지 않은 부분으로 회전합니다.

호그와일드! 논문 (로디오노프 등, 2025) 은 다음과 같은 관찰을 보고합니다.

- 노동자들은 계획을 수립하고 캐시를 통해 다른 노동자들에게 전달합니다.
- 노동자들은 다른 노동자들의 논리 오류를 발견하고 그들을 외치기도 합니다.
- 노동자들은 계획이 실패할 때 적응하고 대안을 제안한다.
- 퇴직자가 있는지 확인하도록 요청되면, 노동자들은 그것을 감지하고 회전합니다.

이 모든 것은 정리가 필요하지 않습니다. 새로운 행동은 이미 모델이 가지고 있는 추론 능력에서 비롯됩니다.

### 이름 붙이는 것

논문의 이름은 애시크론 업데이트 최적화인 Hogwild! SGD (Recht et al., 2011),에 대한 리프입니다. 유사성: SGD의 애시크론 작업자들은 모두 공유된 매개 변수 벡터로 작성하고; Hogwild! 인퍼런스의 작업자들은 모두 공유된 KV 캐시로 작성합니다. 둘 다 동기화 보장보다는 경험적 인 공감에 의존합니다.

### RoPE는 이것을 가볍게 만듭니다.

로터리 포지션 임베디언스 (RoPE, Su et al. 2021) 는 Q 및 K 벡터에서 회전으로 위치 정보를 암호화합니다. 위치가 회전이기 때문에, 토큰의 위치가 KV 캐시 입력을 재회정하지 않고 변경될 수 있습니다. 작업자가 `i`위치에서 공유 캐시에 입력합니다 `p`, 그 위치를 읽는 다른 노동자들은 캐시된 항목을 직접 사용할 수 있습니다.

학습된 위치 또는 절대적 위치 모델에서, 호그와일드는 모든 동시 작성에서 캐시 비효율을 필요로합니다. RoPE는 캐시를 안정적으로 유지합니다.

### 벽 시간 수학

-    `T_serial`한 노동자가 혼자 문제를 해결할 수 있는 시간이 될 수 있습니다.`p`작업 레벨에서 병렬화 될 수 있는 분자가 되겠습니다.`c`단계별 조정 대비를 (장반 캐시를 읽고 무엇을 쓸지 결정하는 것)

단독 노동자 시간: `T_serial`- 그래
N-노동자 호그윈드! 시간, 협조는 무료: `T_serial * ((1 - p) + p / N)`- 클래식 아만달
조정 대비:`T_serial * ((1 - p) + p / N) + c * steps_per_worker`- 그래

노동자가 생산적이기 위해서`c`5k+ 토큰을 생산하는 추론 모델에서는 노동자들이 수백 개의 조정 토큰을 감당하고 여전히 앞서 나갈 수 있습니다. 짧은 채팅 작업에서는 조정이 지배하고 호그와일드!는 시리즈보다 더 나쁘습니다.

### 구체적인 예제

논리 문제: 10k 톤의 사상 연쇄. 문제가 있다고 가정해보자`p = 0.7`병렬화 가능한 내용 (다양한 증명 전략, 다른 사례 분석)`c = 200`일인당 조정 대비를 표시합니다.`N = 4`노동자:

- 일련 시간: 10000 단계의 디코딩
- 호그와일드! 시간: 10000 * (0.3 + 0.7 / 4) + 200 * 4 = 10000 * 0.475 + 800 = 5550 디코드 단계.
- 속도: 10000 / 5550 = 1.8x.

하지만 더 긴 논리 문제 (50k 토큰) 에 있어서 조정 오버헤드가 부과되고 스피드업이 2.5-3x로 증가합니다. 호그와일드는 스레드 레벨 병렬성의 추론적 대칭입니다.

### 호그와일드를 언제 찾아야지!

- 긴 논리 문제 (천 개의 토큰) 에서 작업은 독립적인 하위 목표에서 병렬화 될 수 있습니다.
- 단계별로 생각하는 훈련을 받은 논리 모델은 자기 조정력이 좋지 않습니다.
- 공유된 캐시를 더하기 N 작업자 프로세스를 저장할 수 있는 충분한 VRAM를 가진 단일 노드 배포. 캐시는 공유되지만, 각 작업자는 자체 활성화 메모리를 가지고 있습니다.

### 언제 하지 말아야 하는지

- 짧은 대화, 조정 대상이 지배적이다.
- 동행되지 않는 작업 ( 단일 선형 증명, 단일 컴파일) N=1는 최대입니다.
- 논리적인 모델이 아니라 조율이 나타나지 않습니다.
- 다원 노드 배포. 공유 캐시에는 매우 빠른 크로스 워커 동기화가 필요합니다. 인트라 노드 괜찮습니다. 크로스 노드에는 지연성 재해가 있습니다.

- 두 개의 작업자 프로세스, 각각의 결정적 "LLM"가 알려진 확률로 여러 토큰 카테고리 (워크 토큰, 관찰 토큰, 조정 토큰) 중 하나를 생성합니다.

시뮬레이터는 고정된 단계 예산으로 실행되며,

### 단계 3: 조정 유리스틱

## 사용 하 고

2026년 4월부터 생산에 Hogwild!의 통합은 연구 수준이다. 야덱스/HSE/IST의 참조 구현은 PyTorch 기반이며, DeepSeek-R1 및 QwQ 모델에서 단일 노드 멀티 프로세스 설정을 목표로합니다.

1. 논리 작업 작업 부하를 프로파일하여 탐구 (다중 전략, 사례 분석, 검색) 와 선형의 토큰 분량을 측정하십시오.

3. 개선이 1.3x 이하인 경우, 조정 지배 체제입니다. 단직으로 돌아가십시오.
4. 개선이 1.5x 이상이라면 N=4로 밀어 다시 측정한다. 감소 수익은 일반적으로 N=4-8에 달한다.

가설적 디코딩과 결합: 각 호그와일드! 작업자는 독립적으로 스펙 디코드를 사용할 수 있습니다. 두 개의 스피드업은 ( 대략) 증배되며 3x 스펙 디코드와 1.8x 호그와일드!를 통해 순수한 싱글 작업자 디코딩보다 효과적인 5.4x로 증가합니다.

## 선박

이 교훈은`outputs/skill-parallel-inference-router.md`. 논리 작업 부하 프로파일 (토큰 예산, 작업 병렬성 프로파일, 모델 가족, 배포 목표) 을 고려하면 투표, 생각 나무, 멀티 에이전트, 호그와일드! 및 가설적인 디코딩 전략 사이에 경로를 이동합니다.

## 주요 용어

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Hogwild! | "Parallel workers, shared cache" | N instances of the same LLM running concurrently with one shared KV cache; emergent coordination via self-prompting |
| Shared KV cache | "The coordination medium" | A single growing KV buffer that all workers read and write; enables instant token visibility across workers |
| Emergent coordination | "No training needed" | Reasoning-capable LLMs can read the shared cache and divide work without any fine-tuning or explicit protocol |
| Coordination overhead (c) | "Tokens spent orienting" | The per-worker cost of reading the extended cache and deciding what to do; must stay small vs total decode time |
| Parallelizable fraction (p) | "What can run in parallel" | Task-level parallelism: the fraction of the total work that is not intrinsically sequential |
| RoPE enables Hogwild! | "Rotary positions are shift-invariant" | Because positions are rotations, writing into a shared cache does not require recomputing prior tokens |
| Voting ensemble | "Run N, pick the majority" | The simplest parallel inference topology; useful for classification, less for long-form reasoning |
| Tree of thought | "Branch and prune" | Reasoning strategy that explores multiple branches and prunes; explicit coordination logic |
| Multi-agent framework | "Assign sub-tasks" | Each agent gets a role; a coordinator orchestrates; heavy protocol overhead |
